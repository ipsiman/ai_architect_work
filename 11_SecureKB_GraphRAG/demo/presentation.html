SecureKB

Защищённая база корпоративных знаний: гибридный поиск с графовым расширением, ответы только по документам со ссылками на источники и три контура разграничения доступа — всё в закрытом контуре, на локальных моделях.
Закрытый контур · без внешних API RAG + GraphRAG-lite · LangGraph 130 автотестов гейт качества 0.83–0.87 (порог 0.70) red-team: 19 из 21 атаки отражено
▸ Qwen 2.5 1.5B · llama.cpp · Apple Silicon — без GPU
▸ 100 документов · 3 уровня доступа · PII-маскирование
▸ Презентация offline · метрики сняты с живого стенда
01 · Проблема

LLM не знает границ корпоративных данных

типичные риски корпоративного ИИ-ассистента
сотрудник: какой бюджет у закрытого проекта?
голая LLM: по моим данным, примерно 120–180 млн…
# уверенная выдумка: модель не видела документ — но ответила
сотрудник (нет прав на документ): покажи отчёт
наивный RAG: находит секретный чанк и цитирует его всем
# поиск не различает пользователей — утечка встроена в конвейер
Две беды на одном конвейере: галлюцинации, когда данных нет, и утечки, когда данные есть, но чужие. SecureKB закрывает обе — конвейером, а не обещаниями.

Галлюцинации

Модель без контекста угадывает. Решение — отвечать только по найденным документам, с цитатой [N] в каждом ответе; нет документа — честный отказ.

Утечки по уровням доступа

Векторный поиск сам не знает про RBAC. Решение — ACL на каждой ветке поиска и контрольная проверка перед генерацией.

Prompt injection и PII

«Проигнорируй инструкции» и персональные данные в запросах. Решение — guardrails на входе и выходе + журнал аудита.

02 · Решение

Три ветки поиска, один конвейер гарантий.

LangGraph · query-граф (State Machine)
вопрос → input_guard → dense · lexical · graph → RRF + ACL-контроль
        → LLM (цитаты) → output_guard → SSE-стриминг
# каждая стадия — узел графа: трейсится, метрится, тестируется
# инъекция? → conditional edge сразу в END, без трат на поиск

Dense — Qdrant

Мультиязычные эмбеддинги e5-small, 384 измерения, pre-filter по ACL прямо в payload чанка.

Lexical — BM25

Точные формулировки и номера. Индекс на каждый уровень доступа — изоляция вместо фильтрации.

Graph — связи сущностей

Вопрос через сущность находит документы без общих слов. Соседи фильтруются по ACL пользователя.

RRF-слияние + контрольная проверка. Веткти объединяются по рангам (Reciprocal Rank Fusion), после чего любой чанк выше уровня пользователя выбрасывается и попадает в аудит — защита от собственных ошибок (defense-in-depth).

04 · Безопасность

Три контура доступа + guardrails + аудит

контур 1 Pre-filter Qdrant

Векторный поиск идёт только по чанкам с меткой ≤ уровня пользователя. Секретные векторы физически не возвращаются.

контур 2 Изолированные BM25

Лексический индекс строится на каждый уровень отдельно: у guest просто нет индекса с секретными чанками.

контур 3 Контроль после RRF

Финальная проверка каждого чанка перед LLM. Прорвавшийся чанк выбрасывается + событие acl_drop в аудит.

Без LLM-судьи

Оценку «той же моделью» отвергли (ревью архитектора: судья слабее подследственного). Только детерминированные проверки: цитата найдена, отказ корректен, секретов нет.

Регресс на каждый PR

Гейт качества и полный конвейер безопасности гоняются одной командой — расхождение ловится до ревью кода.

Найдено нагрузкой и закрыто: при конкурентности ≥2 SSE-стримы роняли сервер (SIGSEGV — один непотокобезопасный llama.cpp-контекст из threadpool). Исправление: decode-lock, сериализация генерации. После фикса — ноль ошибок, латентность растёт как очередь, а не как сбой.

Узкое место — LLM

Ретрив: десятки миллисекунд (~1%). Prefix-обработка промпта: ~85% времени. Видно по стадиям в Jaeger и по p95-гистограммам стадий в Prometheus.

Потолок одного инстанса

~0.27 RPS — генерация сериализована. Масштабирование — горизонтально (инстансы) или вертикально (GPU).

Целевая схема — vLLM

Continuous batching на GPU снимает сериализацию: параллельные запросы батчатся в один проход декодера. Зафиксировано в ADR-001 и плане перехода.

6 ADR · по 3–5 альтернатив

Каждое решение зафиксировано в формате ADR: контекст, альтернативы с плюсами/минусами, последствия и план снятия ограничения в целевой архитектуре.

Отступления — легальны

4 отступления от полного ТЗ оформлены по требованию курса: ограничение + допущение + снижение риска. Пример: мультимодальность отложена — нет GPU для VLM.

Ядро переживёт апгрейд

LLM за протоколом, поиск за интерфейсами: замена llama.cpp → vLLM не трогает guardrails, тесты и конвейер.
