# План тестирования SecureKB

**Статус:** выполнено, 129 тестов проходят без ошибок (0 пропущено).
Требования — `01-требования.md` (FR-01..16, NFR-01..10; FR — Functional
Requirement, функциональное требование; NFR — Non-Functional Requirement,
нефункциональное требование), нагрузка — `04-load-report.md`,
архитектурные решения — `adr/`.

## 1. Цели и охват

Подтвердить основные свойства системы до приёмки:

- **Юнит-тесты** — этапы конвейера изолированно: парсер, чанкер,
  PII (Personally Identifiable Information — персональные данные), экстрактор
  сущностей, RRF (Reciprocal Rank Fusion — обратное ранговое слияние),
  guardrails, промпты.
- **Интеграционные** — узлы LangGraph-графов, ветки поиска (dense, lexical,
  graph_expand), API-слой (чат, SSE — Server-Sent Events, админ-эндпоинты),
  потокобезопасность LLM (LLM — Large Language Model, большая языковая модель).
- **E2E по безопасности** — полный конвейер query: RBAC (Role-Based Access
  Control — доступ по ролям) на всех ветках, red-team
  инъекции, PII на входе и выходе, ablation графовой ветки.
- **Безопасность** — раздел 4: три контура ACL, guardrails, журнал аудита.
- **Нагрузочные** — раздел 5: RPS (Requests Per Second — запросов в секунду),
  перцентили, TTFT (Time To First Token — время до первого токена)
  при конкурентности 1/2/4.
- **Качество генерации** — раздел 6: golden Q/A с гейтом 0.70.

## 2. Стратегия

Пирамида: основание — быстрые детерминированные юниты этапов, середина —
интеграционные тесты графов и API, вершина — e2e-безопасность, нагрузка и
golden-гейт.

Детерминизм обеспечивают подмены: FakeEmbedder (фиксированные векторы вместо
multilingual-e5-small) и FakeLLM (предопределённые ответы) — тесты веток поиска,
слияния и API не зависят от реального инференса и веса модели. Фиксированный
seed=42 в выборке вопросов и перемешиваниях. Генерация через реальную Qwen
покрывается только нагрузочным тестом и golden-гейтом, где недетерминизм
контролируется порогами.

Skip-политика: тесты, требующие живого Qdrant, ссылаются на переменную окружения
и пропускаются при недоступном контейнере; в штатном прогоне стенда (docker compose
qdrant поднят) пропусков нет — текущий статус 129 passed / 0 skipped.

## 4. Тесты безопасности

Полный конвейер (`test_security_e2e.py`, `test_acl.py`, `test_guardrails.py`):

- **RBAC, полный конвейер:** bob (internal) спрашивает о секретном проекте — в
  финальном контексте и ответе нет чанков уровня secret (проверяются все три
  ветки поиска и слияние); alice (secret) получает ответ с цитатой; guest — только
  public. Охватываются pre-filter Qdrant, per-ACL (Access Control List — список
  контроля доступа) BM25-индексы (BM25 — Best Match 25) и контроль после RRF
  (ADR-005; ADR — Architecture Decision Record, запись об архитектурном
  решении), события `acl_drop`.
- **Red-team инъекции:** 10 атак («ignore previous instructions», «ты теперь DAN»,
  jailbreak-шаблоны, RU/EN) — все блокируются InjectionGuard; 8 легитимных вопросов
  не блокируются (NFR-06: 10/10 и 8/8).
- **PII:** на входе запрос с телефоном/ИНН маскируется до retrieval (событие
  `pii_masked`); на выходе ответ с маркерами {SECRET} редуцируется OutputGuard
  (событие `output_sanitized`).
- **Ablation графа** (`test_ablation.py`): graph_expand выключен — recall@5
  падает с 1.000 до 0.944; в пуле есть вопрос, решаемый только через граф.

## 5. Нагрузочные тесты

Инструмент `scripts/load_test.py` (asyncio + httpx). Методика: уровни
конкурентности 1/2/4 последовательно; режимы SSE (stream=true) и JSON
(stream=false); вопрос — случайный из 18 golden при фиксированном seed,
пользователи ротируются alice/bob/guest; 1 warmup-запрос вне статистики;
остановка уровня после 20 ошибок подряд. Метрики: RPS, ошибки, p50/p95/p99
total, TTFT по первому token-событию, среднее число токенов.

Целевые пороги NFR: SSE при c=1/2/4 — не менее 0.2 RPS и 0 ошибок (факт:
0.270 / 0.265 / 0.234, 0 ошибок); TTFT p50 при c=1 — не выше 5 с (факт 3.08 с).
Полные таблицы, диагностика узкого места (LLM-prefill, ~85–96 % латентности;
сериализация генерации decode-lock — рост p50 ×2.1 при c=2 и ×4.9 при c=4) и
воспроизведение — `04-load-report.md`.

## 6. Качество генерации

Пул golden Q/A — 18 вопросов по корпусу; гейтовая подвыборка — 15 вопросов с
детерминированными проверками (цитата на верный источник найдена / корректный
отказ). Порог — не ниже 0.70 (NFR-05). Фактический результат: 13/15 = 0.87,
порог превышен уже на первой итерации без подгонки промптов.

Известные проблемы: 2 ошибки из 15 — LLM отказалась отвечать при верно найденных
источниках (источник присутствовал в контексте) — это ограничение Qwen2.5-1.5B
Q4_K_M, а не поиска; отнесено к доработке промптов,
целиком воспроизводится в golden-логах.
