# Совокупная стоимость владения (TCO) и окупаемость

Статус: оценка. Все суммы — консервативные порядки величин, помечены «оценка»; точные котировки сознательно не подставляются. Валюта — USD для сопоставимости.

## 1. Модель затрат

Классы затрат:

- **CAPEX** (Capital Expenditure) — разовые капитальные вложения: закупка серверов и GPU, первичная разработка и внедрение.
- **OPEX** (Operational Expenditure) — операционные расходы: аренда, электричество, сопровождение, обучение персонала.

Категории:

1. **Инфраструктура** — вычисления (GPU/CPU), хранение, сеть, электропитание.
2. **Лицензии ПО** — весь стек open-source (FastAPI, LangGraph, Qdrant, Neo4j, vLLM, Vault, Prometheus/Grafana/Jaeger): 0.
3. **Разработка и поддержка** — доля FTE (Full-Time Equivalent — одна штатная единица) инженеров; обучение моделей не предусмотрено (используются только pre-trained модели).
4. **Обучение персонала** — администраторов и первых пользователей.

## 4. Сравнение с альтернативой «облачные API LLM»

Заданием внешний API запрещён (закрытый контур), поэтому сравнение — только экономическое. Оценка объёма: 500 сотрудников × 5 запросов/день × 400 токенов = 1 млн токенов/день (~30 млн/мес). С RAG-контекстом промпт в 3–5 раз длиннее ответа — реальный расход умножается (строка «×4»).

Цена API: порядок 0,5–5 $ за 1 млн токенов (оценка, зависит от модели).

| Запросов/день | Токенов/мес | API, $/год (оценка) | С RAG-контекстом ×4, $/год (оценка) | Локально, $/год (оценка) |
|---|---|---|---|---|
| 1 000 | 12 млн | 70–720 | 300–2 900 | 20 000–42 000 |
| 10 000 | 120 млн | 720–7 200 | 2 900–28 800 | 20 000–42 000 |
| 100 000 | 1,2 млрд | 7 200–72 000 | 28 800–288 000 | 20 000–42 000 |

Кривая API растёт линейно с объёмом; локальная платформа почти плоская (одна GPU-нода с vLLM-батчингом закрывает десятки тысяч запросов в день — экстраполяция выводов отчёта 04). Точка безразличия — порядка десятков тысяч запросов в день (оценка).

Но экономика — не главный аргумент: внешний API означает передачу конфиденциальных документов третьей стороне (риск утечки, договорные и регуляторные ограничения), постоянную валютную зависимость и привязку к провайдеру. В малом масштабе API дешевле локального контура; при росте нагрузки и требовании конфиденциальности локальная платформа выигрывает по совокупности цена/риск.

## 5. Окупаемость

Формула годовой экономии времени сотрудников:

`Э = N × Δt/60 × C × D × A`

- N — успешных поисков в день по всей компании;
- Δt — экономия времени на поиск: 15 мин → 2 мин, Δt = 13 мин (допущение-оценка);
- C — стоимость часа сотрудника с накладными расходами: 25 $ (оценка, диапазон 15–40 $);
- D — 220 рабочих дней в году;
- A — доля случаев, когда платформа закрыла поиск (уровень внедрения).

Пример: 500 сотрудников, 1 поиск/день каждый, A = 25 %:
`Э = 500 × 13/60 × 25 × 220 × 0,25 ≈ 149 тыс $/год` (при A = 100 % — до 596 тыс $/год, оценка).

Порог безубыточности: годовая TCO целевой конфигурации ≈ 25 тыс $ (середина диапазона). Один регулярно ищущий сотрудник экономит `13/60 × 25 × 220 ≈ 1 190 $/год`; значит, безубыточность достигается уже при ≈ 20–25 успешных поисках в день по компании (около 4–5 % сотрудников).

Допущения: Δt и C — порядки; экономия монетизируется не полностью (не всякое сэкономленное время дефицитно); эффект подтверждается только на вопросах, закрытых базой (golden Q/A как прокси покрытия).

## 6. Вывод

Локальная платформа выгодна, когда: (1) данные конфиденциальны и контур обязан быть закрытым — тогда внешний API исключён неценовым ограничением; (2) объём достигает десятков тысяч запросов в день или устойчиво растёт — локальная кривая затрат плоская; (3) есть горизонт ≥ 2–3 года (выгоден on-prem либо длительная аренда) и выделенная доля FTE — главная статья TCO. В малом масштабе с неконфиденциальными данными дешевле облачный API — но это не сценарий SecureKB.
