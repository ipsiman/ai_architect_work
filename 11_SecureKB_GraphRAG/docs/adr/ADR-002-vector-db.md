# ADR-002: Векторная база данных

**Статус:** Принято (2026-10-26).

## Контекст

Плотная ветка гибридного поиска требует хранилища эмбеддингов (multilingual-e5-small,
384 измерения, 100 чанков MVP (Minimum Viable Product — минимально жизнеспособный
продукт) с запасом на рост) с фильтрацией по метке доступа
(public / internal / secret) на стороне поиска и процедурой бэкапа. Ограничения:

- закрытый контур: только self-hosted решения, развёртывание через docker compose;
- macOS-стенд без кластерных ресурсов;
- фильтрация ACL (Access Control List — список контроля доступа) обязана выполняться в момент поиска (pre-filter), а не после;
- нужен программный бэкап/восстановление коллекции (snapshot API).

## Рассматриваемые альтернативы

| Вариант | Плюсы | Минусы | Почему нет |
|---|---|---|---|
| Milvus | Масштабируемость, миллиарды векторов, режимы индексов | Тяжёлый стек: etcd, MinIO, несколько контейнеров | Избыточен для MVP, усложняет compose и поддержку |
| Weaviate | Зрелый продукт, гибридный поиск из коробки, модульность | Ориентация на GraphQL-API, меньше русскоязычного сообщества и материалов поддержки | Сложнее диагностика и обмен опытом; REST/gRPC-интерфейс Qdrant ближе к задаче |
| pgvector | Один PostgreSQL на данные и векторы, SQL-фильтры произвольной сложности | Тянет за собой PostgreSQL; гибридный (плотный + лексический) поиск слабее из коробки | В MVP нет эксплуатируемого PG; лексическая ветка всё равно своя (BM25 — Best Match 25) |
| Qdrant | Лёгкий single-binary контейнер, payload-фильтры в поиске, snapshot API, Rust | Не самый большой масштаб сообщества | — |

## Решение

Принято: **Qdrant v1.12.5 в Docker** (контейнер securekb-qdrant). Обоснование по
критериям:

- соответствие ограничениям: один контейнер, self-hosted, работает на macOS arm64;
- MVP-бюджет: минимальная эксплуатационная нагрузка, REST API покрывается без
  промежуточных зависимостей;
- расширяемость: ACL реализуется payload-фильтром `MatchAny` по уровню пользователя
  (acl ≤ user) прямо в запросе поиска, snapshot API закрывает FR-16 (бэкап коллекции
  скриптом backup.sh).

## Последствия

**Плюсы:** pre-filter ACL без отдельной логики хранения; детерминированный поиск
с фильтром; восстановление из снапшота одной командой; латентность плотной ветки
в составе retrieval ~20–48 мс (доли процента от полной задержки запроса).

**Минусы и риски:** single-node инстанс без репликации — нет высокой доступности
(HA); фильтр по payload требует дисциплины: метка acl обязана проставляться при
ингесте (проверяется тестами test_acl, контроль дублируется третьим контуром ACL — ADR-005).

**Целевая архитектура:** Qdrant в кластерном развёртывании (репликация, шардинг)
либо переход на Managed-вариант при переносе в ДЦ; при росте корпуса и требований
к гибридности — пересмотр в пользу Milvus, если масштаб превзойдёт возможности
single-node Qdrant.
