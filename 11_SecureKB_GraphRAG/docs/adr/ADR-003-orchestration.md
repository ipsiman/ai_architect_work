# ADR-003: Оркестрация конвейера

**Статус:** Принято (2026-10-26).

## Контекст

Конвейер запроса и ингеста — многоэтапные цепочки с ветвлениями: блокировка запроса
guardrail-ом завершает обработку досрочно (conditional edge в END), три ветки поиска
расходятся параллельно и сходятся в слиянии, перед генерацией обязателен контрольный
ACL-этап. Задание прямо требует «State Machine, не линейные скрипты». Ограничения:
закрытый контур (локальные компоненты), один процесс приложения, воспроизводимость
для тестов и трейсинга этапов.

## Рассматриваемые альтернативы

| Вариант | Плюсы | Минусы | Почему нет |
|---|---|---|---|
| LangGraph (StateGraph) | Явный граф состояний, условные рёбра, точка ветвления и досрочного выхода, готовая интеграция трейсинга узлов | Ещё одна зависимость, собственная модель состояния | — |
| LlamaIndex | Готовые RAG-абстракции, быстрые прототипы | Фреймворк навязывает свой поток: меньше контроля над порядком guardrails-этапов и ветвлением, «магия» middleware | Контроль над потоком безопасности критичен; скрытые абстракции мешают точечной диагностике |
| Линейный asyncio-пайплайн | Просто, без зависимостей, читается сверху вниз | Нет точек ветвления и возобновления; условные выходы — вложенные if; нарушает прямое требование задания («линейные цепочки запрещены») | Прямое несоответствие заданию; сложность растёт нелинейно с числом условий |

## Решение

Принято: **LangGraph StateGraph** как тонкая машина состояний поверх этапов.

- `query_graph`: input_guard → dense → lexical → graph_expand → fuse_rerank →
  generate → output_guard; conditional edge из input_guard в END при блоке запроса.
- `ingest_graph`: аналогичный граф этапов ингеста (парсинг → чанкинг → PII → ACL →
  эмбеддинг → запись в Qdrant; параллельно экстракция сущностей → запись графа).

Критерии: соответствие ограничениям (требование задания выполнено буквально),
бюджет MVP (Minimum Viable Product — минимально жизнеспособный продукт;
тонкая обёртка, этапы — обычные функции, тестировать можно без
LangGraph-рантайма), расширяемость (новый этап — узел и ребро, без перекройки
потока). Отступление О-4 зафиксировано: LangGraph используется именно как
State Machine, а не как фреймворк RAG.

## Последствия

**Плюсы:** досрочный выход при блоке guardrail без затрат на retrieval; граф
воспроизводится в документации и трейсах Jaeger (спан на узел); параллельные ветки
поиска соединяются явно.

**Минусы и риски:** зависимость от эволюции LangGraph; состояние графа — словарь,
ошибки типов не выявляются статически (компенсируется тестами этапов и контрактом
состояния).

**Целевая архитектура:** структура графа сохраняется; при выносе стадий в сервисы
(отдельный retrieval-сервис, vLLM-инференс) узлы становятся вызовами распределённых
этапов без изменения топологии. Запасной вариант при деградации LangGraph —
собственный конечный автомат с той же топологией, изоморфно отражаемой в коде.
