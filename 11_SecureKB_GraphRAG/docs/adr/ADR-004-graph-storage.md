# ADR-004: Хранение графа знаний

**Статус:** Принято (2026-10-26).

## Контекст

Графовое расширение запроса (GraphRAG-lite) требует хранения онтологии из четырёх
типов узлов (Document, Person, Project, Department) и рёбер со-встречаемости
сущностей, а также операции «соседи документа с фильтром по списку разрешённых
документов» — neighbours(allowed_doc_ids). Демонстрационный корпус: 20 узлов,
276 рёбер; экстракция rule-based (gazetteer), без LLM. Ограничения: закрытый
контур, macOS-стенд docker compose, бюджет MVP, необходимость согласованного
бэкапа с Qdrant и простого визуального демо графа.

## Рассматриваемые альтернативы

| Вариант | Плюсы | Минусы | Почему нет |
|---|---|---|---|
| Neo4j | Полноценный графовый движок, Cypher, обходы переменной глубины, визуализация | Отдельный сервер (JVM), лицензионные ограничения Community-редакции, рост стека | Избыточен для масштаба MVP (Minimum Viable Product, минимально жизнеспособный продукт) и rule-based экстракции; отступление О-3, целевой вариант |
| NetworkX (в памяти) | Ноль инфраструктуры, богатые алгоритмы | Нет персистентности и конкурентности: граф живёт в процессе, пересборка при рестарте | Не выдерживает рестарты и параллельные чтения при ингесте; бэкап только сериализацией |
| PostgreSQL + AGE | SQL-экосистема, графовые запросы поверх реляционного хранилища | Тянет за собой PostgreSQL ради одного графа; расширение AGE добавляет эксплуатационную сложность | В MVP PostgreSQL нигде не используется; избыточно |
| SQLite (nodes/edges) | Встроенный, нулевая эксплуатация, транзакции, `sqlite3 .backup` | Нет графовых запросов — обход вручную SQL-соединениями | — |

## Решение

Принято: **SQLite** — таблицы `nodes` и `edges`, ключевая операция — запрос соседей
`neighbors(allowed_doc_ids)` (JOIN рёбер с узлами и фильтром по списку документов,
доступных пользователю). Критерии: соответствие ограничениям (встроенный,
self-hosted), MVP-бюджет (масштаб 20 узлов / 276 рёбер — миллисекунды на SQL),
расширяемость (узкий интерфейс соседей изолирует хранилище от логики graph_expand).
Бэкап — согласованная копия graph.db через `sqlite3 .backup` вместе со снапшотом
Qdrant (FR-16).

## Последствия

**Плюсы:** транзакционная согласованность узлов и рёбер; графовое расширение —
~1 % латентности запроса вместе с остальным retrieval; визуализация graphviz PNG
для демо строится напрямую из SQLite.

**Минусы и риски:** обходы глубины > 1 — рекурсивные CTE, производительность на
больших графах деградирует; rule-based экстрактор ограничен словарём (новые
сущности не выявляются). Польза графа доказана ablation-тестом: recall@5
1.000 с графом и 0.944 без него.

**Целевая архитектура:** Neo4j с LLM-экстракцией сущностей (снятие О-3): Cypher-обходы
переменной глубины, полноценные графовые алгоритмы; интерфейс neighbors сохраняется,
миграция данных — экспорт nodes/edges в CSV/Cypher-LOAD. PostgreSQL+AGE остаётся
запасным вариантом при уже эксплуатируемом PG.
