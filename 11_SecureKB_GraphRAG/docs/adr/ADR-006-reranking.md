# ADR-006: Слияние и re-ranking результатов поиска

**Статус:** Принято (2026-10-26).

## Контекст

Три ветки поиска (плотная Qdrant, лексическая BM25 (Best Match 25), графовое расширение) возвращают
несовпадающие ранжированные списки кандидатов; для генерации нужен один
детерминированно упорядоченный контекст. Баллы веток несравнимы между собой
(косинусная близость, BM25-скор, позиция графа), поэтому слияние обязано не зависеть
от шкал. Ограничения: суммарный бюджет моделей < 2 ГБ уже занят LLM и эмбеддером;
узкое место конвейера — LLM-инференс, латентность re-ranking пренебрежима, но не
бесплатна; порядок должен воспроизводиться в тестах.

## Рассматриваемые альтернативы

| Вариант | Плюсы | Минусы | Почему нет |
|---|---|---|---|
| Cross-encoder (ранкер поверх пар запрос-чанк) | Точная релевантность, лучшее качество ранжирования | Третья модель в контуре: выход за бюджет < 2 ГБ, латентность пропорциональна числу кандидатов, дообучение под домен | Бюджет моделей исчерпан; +N прогонов инференса на запрос при уже узком месте — LLM-инференсе |
| LLM-rerank (ранжирование основной моделью) | Не требует новой модели, использует понимание контекста | Дорогой и медленный: полный прогон LLM на каждый кандидат/батч; конкурирует с генерацией за единственный контекст (ADR-001) | Усугубляет узкое место; нет гарантированной детерминированности |
| Без слияния (одна ветка, например только dense) | Простейшая схема | Хуже полнота: лексическая ветка находит точные термины, граф — документы без лексического пересечения; противоречит гибридности и требованию задания | Ablation: полнота падает (recall@5 1.000 → 0.944 без графовой ветки) |
| RRF (Reciprocal Rank Fusion) | Работа с позициями, шкалы не важны; детерминирован; миллисекунды | Не понимает семантику — качество ограничено качеством веток | — |

## Решение

Принято: **слияние RRF с k=60** — для каждого кандидата суммируются вклады
1/(k + rank) по веткам, где он встретился; итоговый порядок детерминирован
(устойчивое разрешение равных сумм). Порог отсечения контекста фиксирован. Критерии:
соответствие ограничениям (ноль дополнительной памяти и моделей), бюджет
MVP (Minimum Viable Product — минимально жизнеспособный продукт; алгоритм —
десятки строк, латентность незначима на фоне LLM), расширяемость
(веса веток и k — конфигурируемые параметры; cross-encoder подключается после RRF
как следующий этап).

## Последствия

**Плюсы:** сопоставление несравнимых шкал без нормализации; повторный прогон даёт
тот же порядок (тест test_rrf); вклад каждой ветки измерим — ablation-тест
подтверждает прирост полноты от графовой ветки (1.000 против 0.944 recall@5).

**Минусы и риски:** RRF нечувствителен к абсолютной нерелевантности — кандидат из слабой ветки
с высокой позицией может вытеснить релевантный (компенсируется порогом и качеством
веток); k=60 — эмпирическая константа без подбора по валидационной выборке.

**Целевая архитектура:** двухступенчатая схема — RRF как coarse-этап (recall),
затем cross-encoder (bge-reranker, отдельная GPU-нода рядом с vLLM) как точное
переранжирование top-N; LLM-rerank не рассматривается как штатный вариант.
